# Real-world WLD validation

Validated on 2026-10-09 with two genuine, locally available WLD files. Neither world was generated by a fixture builder. Source identities, paths, names, coordinates, hashes, world contents, and generated screenshots are intentionally excluded from this public report. No world files or resource packs were uploaded or added to the repository.

| --- | --- | --- | --- |

| B | 326 | 8400 × 2400 | 11,956,596 |

## Confirmed results

Both cases passed the native engine proof, the shipped Web WASM proof, and the Flutter Workspace proof: six successful real-file proof cases in total. Flutter reported two passing tests. The WASM runtime was executed locally through Node and the production JavaScript bridges; this was not a browser file-picker or browser UI test.

- Parse the actual version, dimensions, header, chest inventories, format metadata, and bestiary.
- Export an untouched world byte-for-byte identically, including after map preview generation.
- Generate valid 960 × 274 map PNGs. All PNGs were fully decoded, and representative output was visually inspected.
- Change time, one boolean world property, and a chest name; save a complete candidate and independently reopen it.
- Compare the entire reopened header and every chest slot against the expected values. Unchanged world sections remain byte-for-byte identical.
- Produce byte-identical edited candidates through Native, Web WASM, and Flutter Workspace.
- Read all layers in a genuine 32 × 32 region, change one wire bit, export a complete world, and independently read back the region. Native and WASM return identical layer records and identical edited world bytes.
- Reject an invalid application edit without changing the last valid candidate.
- Exercise the application's actual world undo/redo history and recover the exact original world bytes. Exercise region undo/redo and restore the complete region records and object companion.
- Validate the local resource pack, render real region texture previews into 512 × 512 PNGs, and preserve both source files unchanged.

## Regression found and fixed

Real-file testing exposed an export-validation defect in the Web bridge: a length-changing chest name correctly moved later WLD section offsets, but save validation compared the old offsets against the reopened candidate and rejected the valid export.

The bridge now excludes derived offset values from logical equality while retaining the offset count, every other format field, and all logical content. The parser still validates the actual offsets. Both real files passed the complete WASM proof after the fix.

The committed regression uses only the original synthetic fixture:

```sh
node test/web/world_export_smoke.cjs
```

It covers changing header lengths and chest-name growth, shrinkage, UTF-8, and empty strings; repeated-save byte stability; independent reopen; full logical readback; invalid-edit recovery; exact reversal; and source-file preservation.

## Limits

- Both WLD versions parsed as known and writable. This proof does not establish support for every WLD version or every game object.
- Texture previews are static approximations. The tested regions had 48 and 89 visible cells with unsupported frame geometry; those cells retained explicit missing-frame markers. Most ordinary blocks and walls used approximate static frames. Rendering a PNG does not mean every game texture or animation is supported.
- Reverse-writing original region records restores the selected layer content but can re-encode tile runs. Exact whole-file undo was therefore separately verified through the application's original-byte history snapshots.
- This is local Native/WASM/Flutter Workspace coverage. It does not certify Android, iOS, browser file-picker interactions, or production deployment.
- A Git LFS pointer was identified and excluded; case B used the verified materialized payload.
